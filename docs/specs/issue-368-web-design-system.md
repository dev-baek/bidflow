# BidFlow 전 화면 디자인 시스템과 UI 개편 사양

- 상태: 리뷰 대기
- 상위 이슈: [#368 전 화면 UI 개편](https://github.com/dev-baek/bidflow/issues/368)
- 범위: 현재 React·TypeScript·Vite 웹의 모든 라우트와 오류·빈 상태. 입찰·정산 규칙, 인증 계약, API·DB·AWS는 유지한다.

## S. 화면과 사용자 흐름

첫 화면에서 경매를 둘러보거나 상품을 등록할 수 있어야 한다. 목록에선 가격과 마감을 비교하고, 상세에선 현재가·마감·입찰 동작을 곧바로 찾을 수 있게 한다. 문구는 사용자의 상태와 다음 행동을 설명한다. 내부 이슈 번호, 헤더 이름, 저장소 오브젝트 키는 사용자 화면에서 제거한다.

| 화면 | 우선 정보와 행동 | 필수 화면 상태 | 이슈 |
|---|---|---|---|
| 로그인 `/login`, 인증 콜백 `/auth/callback`, 보호 라우트 | 로그인 방법과 다음 행동. 로컬에서는 “테스트용 ID를 입력하세요”; Cognito에서는 로그인 시작·재시도만 노출 | 빈 ID, 인증 중·실패·만료, 보호 경로 진입과 기존 리다이렉트 | #370 |
| 홈 `/`, 공통 탐색 | 경매 둘러보기 우선, 상품 등록 보조. 현재 위치와 로그인·로그아웃을 쉽게 찾을 수 있게 한다 | 비로그인/로그인, 모바일 내비게이션 | #371 |
| 404 `*`, 앱 설정 오류 | 404에는 홈/목록 복귀. 설정 오류에는 운영 비밀값 없이 실행 환경별 복구 안내 | 둘을 서로 다른 화면으로 표시. 앱 초기화 실패는 인증/라우터에 의존하지 않음 | #371 |
| 목록·검색 `/listings` | 검색/필터 → 결과 카드. 카드에서 상품명·현재가·종료 시각·경매 상태를 같은 위치에 표시 | 검색 전·로딩·빈 결과·오류·재시도·다음 결과·이미지 없음 | #372 |
| 상품 등록 `/listings/new` | 상품 정보 → 경매 조건 → 이미지. 입력값과 제출 결과를 한 흐름에서 확인 | 필드 오류, 이미지 업로드 중·실패·재시도, 제출 중·성공·실패. 성공 시 생성된 상세로 이동할 링크 | #373 |
| 경매 상세 `/auctions/:auctionId` | 제목·이미지, 현재가와 마감, 공개 결과. 넓은 화면은 상세/입찰 2열, 좁은 화면은 현재가·마감 바로 다음에 입찰 영역 | 조회 중·없음·오류, 오래된 값/재조회, 시작 전·진행·종료, 공개 낙찰/유찰 | #374 |
| 상세 안의 입찰 폼과 내 결과 | 직접/자동 입찰 방식을 구분하고, 내 요청과 공개 경매 상태를 분리 | 비로그인, 제출 중, 접수, 승인/거절, 실패·재시도, 개인 결과 조회·오류, 낙찰·패찰 | #375 |

## S. 디자인 토큰과 공통 컴포넌트

밝은 배경, 남색 본문, 파란색 주요 행동으로 한 가지 테마를 사용한다. 아래 값은 구현의 기준이며 화면별로 같은 값을 다시 선언하지 않는다. 색은 원시 팔레트 값이 아니라 역할 이름으로 소비한다. 예를 들어 주요 버튼은 `--color-action`, 현재가는 `--type-price` 계열을 사용한다.

| 색 역할 | 기본값 |
|---|---|
| 페이지 배경 / 카드 배경 / 보조 배경 | `#F8FAFC` / `#FFFFFF` / `#F1F5F9` |
| 본문 / 보조 문구 / 버튼 위 문구 | `#0F172A` / `#475569` / `#FFFFFF` |
| 주요 버튼 기본 / hover / active | `#1D4ED8` / `#1E40AF` / `#1E3A8A` |
| 구분선 / 입력 경계 / 포커스 | `#E2E8F0` / `#64748B` / `#2563EB` |
| 정보 문구·배경 | `#1E40AF` · `#EFF6FF` |
| 성공 문구·배경 | `#166534` · `#F0FDF4` |
| 주의 문구·배경 | `#92400E` · `#FFFBEB` |
| 오류 문구·배경 | `#B91C1C` · `#FEF2F2` |
| 비활성 문구·배경 | `#475569` · `#E2E8F0` |

| 규칙 | 값 |
|---|---|
| 폰트 | `system-ui, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`. 가중치 400/500/600/700. 가격·남은 시간은 `tabular-nums`와 원화 표기 사용 |
| 글자 크기 / 줄 높이 | 보조 12/16, 라벨·보조 본문 14/20, 본문 16/24, 카드 제목 20/28, 섹션 제목 24/32, 페이지 제목 32/40, 홈 강조 제목 40/48, 현재가 28/36. 기본 루트 16px 환산값이며 CSS는 `rem`으로 작성 |
| 간격 | 4, 8, 12, 16, 24, 32, 48, 64px 환산. 모바일 좌우 여백 16, 태블릿 24, 데스크톱 32 |
| 버튼과 입력 | 버튼 sm/md/lg 최소 높이 36/44/52px, 좌우 여백 12/16/24px, 폰트 14/14/16px. 입력·셀렉트 기본 최소 높이 44px, 폰트 16px. 주요 터치 동작과 아이콘 버튼 최소 44×44px. 긴 문구는 고정 높이 대신 줄바꿈 허용 |
| 모서리 / 포커스 | 입력·버튼 8px, 카드 12px, 메시지 패널 16px, 배지 pill. 포커스는 2px 표시 + 2px 간격; 강한 색 표면에는 대비가 나오는 이중 링 또는 흰 간격 사용 |
| 화면 폭 | 본문 최대 1200px, 로그인 최대 440px, 등록 폼 최대 760px. 768px부터 목록 2열, 1024px부터 목록 3열·상세 2열. 그 아래 목록/상세는 1열 |

- **버튼과 링크:** primary, secondary, ghost의 세 가지를 기본으로 한다. 실제 위험 동작이 있을 때만 오류 색을 쓴다. 로딩은 레이블과 함께 보이고 중복 요청을 막는다. 페이지 이동은 링크, 폼 제출과 상태 조작은 버튼으로 둔다.
- **입력:** 입력·셀렉트·텍스트 영역·파일 입력에 라벨/도움말/인라인 오류를 연결한다. placeholder는 라벨을 대체하지 않는다. 첫 오류에 접근할 수 있게 하고 오류 때문에 작성한 값이나 성공한 업로드가 사라지지 않게 한다.
- **상태와 카드:** 로딩·빈 상태·오류·성공은 공통 패턴을 사용한다. 배지는 색만으로 뜻을 전달하지 않는다. 상품 카드의 이미지 영역은 4:3, 잘림은 썸네일에만 적용한다. 이미지 주소가 없거나 로딩에 실패하면 같은 비율의 대체 영역을 렌더링한다.

## D. 표시 데이터와 보호 경계

- 기존 API가 제공하는 값만 표시한다. 현재 웹은 키를 받는 경우가 있으므로, 브라우저가 읽을 수 있는 기존 이미지 주소가 없으면 대체 영역을 사용한다. 키로 공개 스토리지 URL을 조립하거나 공개 권한을 추가하지 않는다.
- 서버의 가격·상태·종료 시각을 기준으로 한다. 남은 시간은 보조 표시이며 종료 판정에는 쓰지 않는다. 서버가 연장된 종료 시각을 반환하면 교체한다. 화면에 시간대를 명시하고 기존 검색 요청의 UTC 변환 방식은 바꾸지 않는다.
- HTTP 접수, 입찰 승인/거절, 경매 종료, 본인 낙찰/패찰은 각각 다른 상태다. 요청 당시 최고 입찰자를 현재 최고 입찰자나 최종 낙찰자로 표현하지 않는다. 비공개 결과는 인증된 본인에게만 그대로 제공하고, 세션 전환 시 이전 결과가 남지 않아야 한다.
- DB 변경 없음. API 스키마·검색 cursor·JWT/PKCE·입찰 멱등성·웹소켓 재연결·마감 연장 규칙은 그대로 유지한다. 실제 연결 상태를 관측할 수 없으면 “연결됨”을 꾸며내지 않고 조회 실패/이전 데이터 표시처럼 확인 가능한 상태를 사용한다.

## B. 프런트엔드 적용 방식

1. #369에서 `apps/web/src/styles/tokens.css`에 색·폰트·공간·크기 변수를 선언하고 기존 `styles.css`에서 한 번만 불러온다. 브레이크포인트는 CSS 사용자 정의 속성으로 미디어 쿼리를 만들지 않고, 합의한 두 값만 스타일에서 사용한다.
2. Button, Field, Badge, 상태 메시지와 페이지 레이아웃은 공유한다. HTML 기본 동작을 살리고, 동일한 마크업·상태가 반복될 때만 React 컴포넌트로 추출한다. 변경한 화면에는 직접 색상 리터럴이나 임의의 버튼 높이를 새로 넣지 않는다. 외부 UI 라이브러리, 웹폰트 CDN, 다크 모드는 이번 범위 밖이다.
3. #370~#374는 공통 테마가 병합된 뒤 각자 적용한다. #375는 #374에서 확정한 입찰 영역에 맞춘다. 페이지 상태는 기존 reducer/adapter를 재사용하고 UI에서 필요한 파생 상태는 순수 함수로 둔다. 새 시각 효과보다 오류·비어 있음·처리 중의 정보 전달을 먼저 완성한다.

## T. 검증과 마감 기준

- 화면별 PR: 현재 상태를 고정하는 테스트부터 작성한다. React Testing Library/Vitest에서 역할과 접근 가능한 이름, 키보드/오류/비활성 상태, 성공·실패·재시도와 늦은 응답을 해당 화면에 맞게 검증한다.
- 통합 #376: 320/390/768/1280px에서 가로 넘침과 화면 잘림이 없어야 한다. Tab/Shift+Tab·Enter로 주요 경로를 확인하고, 포커스가 헤더 등에 가려지지 않아야 한다. 일반 텍스트는 4.5:1, 큰 텍스트와 필수 컨트롤 표시/경계는 3:1을 기준으로 삼는다. 44px 주요 터치 목표는 프로젝트 기준이다. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- 기존 Playwright 핵심 흐름(로컬 로그인 → 등록 → 검색/상세 → 직접·자동 입찰 → 종료 시 공개/개인 결과)과 `make verify`를 확인한다. Cognito는 로컬 대역으로 성공·콜백 실패·만료를 확인하며 실제 AWS 인증 성공으로 표기하지 않는다.
- 각 화면 PR에 데스크톱/모바일 캡처와 바뀐 상태를 남긴다. 디자인 토큰 사용과 모든 화면의 회귀를 확인하기 전에는 상위 #368을 닫지 않는다.
