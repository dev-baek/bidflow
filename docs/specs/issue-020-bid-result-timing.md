- 상태: #281 승인. TDD로 문구와 기존 E2E 단언을 수정하고 [브라우저 3개 사례](../reports/issue-020-bid-result-timing.md)를 검증했다.
- 기존 이슈: [#20 사용자 흐름 E2E](https://github.com/dev-baek/bidflow/issues/20). [경매 상세 화면](issue-213-auction-detail-bid-ui.md)과 [WebSocket 계약](issue-014-realtime-websocket.md)의 개인 결과 표시를 보완한다.
- 근거: [실제 snapshot 시점 차이](../reports/issue-019-concurrent-smoke-failure.md), [판정 수정과 동시 실측](../reports/issue-019-concurrent-snapshot-fix.md).

## 문제와 수정 범위

BidRealtimeKafkaListener는 개인 결과의 isHighestBidder를 BidAccepted 이벤트에서 가져오지만 가격/version은 더 최신인 DB snapshot에서 가져올 수 있다. 승인 이벤트 처리 이후 다른 사용자가 추월해도 해당 flag가 최신 상태로 다시 계산되는 것은 아니다.

현재 BidRequestForm의 “현재 최고 입찰자입니다/아닙니다” 문구는 이 과거 판정을 현재 순위처럼 표현한다. **요청 처리 당시의 사실로 문구를 바꿔** 시점을 명확히 한다. 현재 최고 입찰 여부를 새로 조회하거나 공개 가격만으로 추정하는 기능은 추가하지 않는다.

## S. 문구와 화면 계약

| 요청 상태 | 표시 |
|---|---|
| ACCEPTED, isHighestBidder=true | 입찰이 승인되었습니다. 이 요청 처리 당시 최고 입찰자였습니다. |
| ACCEPTED, isHighestBidder=false | 입찰이 승인되었습니다. 이 요청 처리 당시 최고 입찰자가 아니었습니다. |
| REJECTED | 기존 입찰이 거절되었습니다 안내 유지 |
| 접수/오류/입력 중 | 기존 접수·오류·폼 동작 유지 |

승인 안내는 기존 role=status로 유지한다. 현재가 영역은 최신 공개 snapshot을 계속 표시하며, 과거 승인 안내와 다른 현재가가 함께 보여도 현재 본인이 최고 입찰자라고 단정하지 않는다. 경매 종료 뒤의 본인 낙찰/패찰 표시는 기존 서버 결과를 사용하며 이 문구 수정으로 대체하지 않는다.

금액·방식을 바꾸면 이전 안내를 지우고, 새 요청에는 이전 요청의 개인 결과를 적용하지 않는 기존 계약을 유지한다. 응답을 잃은 재시도와 응답 전에 도착한 개인 결과의 처리도 바꾸지 않는다.

## D. 데이터의 기준 시점

isHighestBidder는 **해당 승인 요청이 처리됐을 때** 수신자가 최고 입찰자였는지를 나타낸다. 현재 사용자 순위의 최신 조회 값이나 최종 낙찰 여부가 아니다. 개인 frame의 currentPrice·auctionVersion이 더 최신이라는 이유로 이 flag의 기준 시점까지 갱신됐다고 해석하지 않는다.

테이블·컬럼·원장·Outbox·메시지 필드를 추가하거나 바꾸지 않는다. 사용자/승자 식별자나 자동 최대가를 공개하는 일도 없다.

## B. 구현 경계

BidRequestForm의 기존 승인 조건과 boolean 분기는 유지하고 표시 문구만 교체한다. 기존 순수 reducer와 개인 frame 파서의 상태/요청 매칭 계약은 변경하지 않는다. 서버 메시지 생성·인증·입찰 엔진·실시간 전파는 그대로다.

수정 대상은 폼의 표시, 컴포넌트 회귀 테스트, 기존 Playwright의 정확한 승인 안내 단언이다. 순차 지연 테스트의 approval locator도 새 문구에 맞추되 요청·가격·개인 결과·화면 완료 조건과 timeout/P95 정의는 유지한다. 단순히 승인이라는 단어만 찾도록 단언을 약화하지 않는다. 동시 관측의 기존 판정 함수와 SQL 연결은 바꾸지 않는다.

## I. 실행과 사양 연결

Vite/Spring Boot의 기존 실행 구조를 사용한다. 새 의존성·환경변수·설정·API·polling은 없다. 기존 WebSocket 문서의 flag 설명과 상세 화면 사양을 이 의미에 맞게 연결한다.

기본 make verify는 서비스 없는 검증으로 유지한다. 브라우저 검증에 local,e2e API가 필요하면 실행 상태와 인자를 기록하고 종료 후 복원한다. AWS·볼륨·Redis 키·offset reset은 사용하지 않는다.

## T. TDD와 인수 기준

1. true/false 승인 결과에 새 과거 시점 문구가 나오고, 현재 최고라고 단정하는 기존 문구가 없다는 컴포넌트 테스트를 먼저 추가해 RED를 확인한다. 거절 결과는 승인으로 표시하지 않아야 한다.
2. 최소 문구 변경 후 GREEN을 확인한다. 다른 requestId 무시, 편집 시 초기화, 재시도 키 재사용, 접수보다 이른 개인 결과와 기존 reducer 회귀 테스트를 유지한다.
3. 기존 직접 입찰 E2E에서 A의 12,000원 승인 뒤 B가 13,000원으로 추월해 양쪽 공개 가격이 바뀌어도 A의 안내는 처리 당시의 사실로 남는지 확인한다. 현재 최고라는 기존 문구는 없어야 한다. 이후 A의 새 14,000원 요청/새 키 검증도 유지한다.
4. 기존 자동입찰 E2E의 true/false 안내를 모두 새 문구로 확인하고, 연장·낙찰/패찰·개인 최대가 비공개 등 기존 단언을 유지한다.
5. 모든 정확한 승인 문구 참조를 점검해 E2E와 순차 지연 locator를 함께 갱신한다. 기존 테스트 제목·관측 시계·threshold는 변경하지 않는다. 전체 Vitest·Node suite·양쪽 build 및 PR CI를 확인하고 실제 브라우저 실행 범위는 별도로 기록한다.

완료 보고에는 RED/GREEN, 실행한 브라우저 사례, 수정한 문구와 남은 한계를 기록한다. 이 수정은 현재 최고 입찰 상태를 실시간 보장하는 기능이 아니라, 기존 개인 결과의 기준 시점을 정확히 표현하는 작업이다.
