## S. 시나리오와 측정 경계

새 로컬 시험 경매와 서로 분리된 두 Chromium context를 사용한다. 테스트 인증·Clock·상품 등록·공개/개인 WebSocket 구독 확인은 기존 Playwright 흐름을 재사용한다. 앱 UI·API와 운영 인증은 변경하지 않는다.

시작가 10,000원, 고정 서버 시각은 마감 10분 전이다. 두 사용자가 번갈아 11,000원부터 30,000원까지 1,000원씩 올려 **총 20건을 순차 제출**한다. 각 입찰은 이전 표본이 확정된 다음에 보낸다. 이 실험은 20개 동시 요청이나 k6의 지속 부하와 다르다.

각 표본은 아래 세 조건을 모두 만족해야 완료다.

1. 제출에 대응하는 HTTP 응답이 `202 RECEIVED`이며 유효한 새 requestId를 반환한다.
2. 같은 requestId·auctionId의 개인 WebSocket 승인 결과를 수신하고, 제출자 화면에 현재 최고 입찰자 승인 안내가 표시된다.
3. 두 화면의 공개 현재가가 해당 제출 금액으로 갱신된다.

## D. 시각과 증적

| 지표 | 같은 테스트 runner의 단조 시계 기준 |
|---|---|
| 시작 | 금액 입력 및 이전 결과 초기화 확인 뒤, 입찰 버튼 `click()` 호출 직전 |
| 접수 관측 | 해당 POST의 응답 본문을 읽은 직후 |
| 개인 결과 수신 | 해당 요청과 일치하는 WebSocket frame을 runner가 관측한 시각 |
| 화면 결과 완료 | 개인 승인 안내와 양쪽 공개 가격을 모두 확인한 직후 |

서버의 테스트 Clock이나 브라우저의 다른 시계와 시각을 빼지 않는다. 이 값에는 Playwright actionability·프로세스 간 전달·assertion polling 대기가 포함되므로 **화면 반영의 자동화 관측 상한**이다. 정확한 paint 시점이나 순수 네트워크 지연이 아니다. 시작을 HTTP 전송 직전으로 둔 DB 관측 지표와 합치거나 같은 백분위로 비교하지 않는다.

개인 결과가 HTTP 응답보다 먼저 도착할 수 있다. 클릭 전에 수신 수집을 시작해 놓친 frame 없이 requestId로 연결한다. 이전 요청 결과를 현재 표본으로 세지 않도록 입력 수정 후 이전 승인 안내가 사라진 것을 확인한다. 공개 가격도 이전 값과 구분되는 새 금액을 사용한다.

표본마다 requestId·경매 ID·금액·접수/개인 결과/최종 화면 상대 시각과 결과를 JSON에 저장한다. 개인 frame 원문·Token·최대 자동입찰가·이미지 URL은 저장하지 않는다. `testInfo.attach`로 성공/실패 모두 결과 파일을 남기고, 실패 trace/screenshot 정책은 기존 설정을 유지한다.

## B/I. 실행과 보조 확인

- 지연 실험은 `BIDFLOW_E2E_LATENCY=1`로 명시적으로 실행한다. 플래그 없이 건너뛴 실행을 실측으로 보고하지 않는다.
- 기존 `local,e2e` API·Vite·Docker를 사용하고, worker 1개로 다른 Clock 변경·부하와 겹치지 않게 실행한다. 회차 timeout은 최대 120초, 각 표본의 결과 대기는 최대 10초로 제한한다.
- 측정 중 새 페이지 진입이나 의도적인 연결 복구를 수행하지 않는다. 준비 단계의 등록·구독 시간은 표본 지연에 넣지 않고 별도로 설명한다.
- 종료 뒤 경매 상세가 현재가 30,000원·version 21인지 확인한다. 해당 시험 경매의 요청·승인 원장·결과 이벤트가 각 20건이며 중복·가격 역행이 없는지 DB로 별도 확인한다. SQL 조회 시간은 화면 지연에 넣지 않는다.
- 다음 회차를 위해 기존 데이터·Redis 키·볼륨을 지우지 않는다. AWS는 사용하지 않는다.

## T. 판정과 한계

- 기존 파서·Reducer 테스트를 유지하며, 요청 ID가 다른 frame·이전 승인 안내·다른 공개 가격으로 표본이 완료되지 않는 경계를 테스트한다.
- 정상 표본 20건을 완료한 경우 nearest-rank P50/P95/P99를 계산한다. 기존 백분위 함수를 재사용할 수 있으면 재사용한다.
- 한 표본이라도 실패하면 앞선 표본과 실패 단계·미완료 개수를 남기고 회차를 실패로 표시한다. timeout을 0ms로 넣거나 완료 표본만으로 전체 성공을 선언하지 않는다.
- 상위 기준의 2초와 비교할 때는 **이 로컬 순차 화면 관측 실험**의 조건을 함께 표시한다. 초과한 회차를 지우거나 느린 첫 표본을 임의로 빼지 않는다. 중간 표본이 2초를 넘더라도 전체 회차를 가능한 범위까지 수집한 뒤 P95를 판정한다.
- 이 결과를 동시 입찰 부하 중 브라우저 P95, 운영 SLO, AWS 배포 성능으로 일반화하지 않는다. 장애·재연결·자동입찰 지연은 기존 기능 E2E와 별개의 미측정 범위다.
