# [Issue #417] 마감과 입찰 정산이 겹칠 때의 확정 기준

- 상태: 검토 요청. 구현과 통합 검증은 별도 PR에서 진행한다.
- 추적: [#417](https://github.com/dev-baek/bidflow/issues/417), [기존 종료 사양](issue-015-auction-close.md), [Redis 복구 사양](issue-416-redis-effective-winner-maximum.md).

Redis의 승인 계산 뒤, PostgreSQL 입찰 정산이 경매 행을 잠그기 전에 종료 작업이 그 행을 먼저 확정할 수 있다. 현재 버전 검사로 경매 재활성화는 막지만, Redis에 남은 승인 계산을 다시 읽으면 요청이 `RECEIVED`에 남을 수 있다. **같은 경매 행을 잠그고 커밋한 PostgreSQL 트랜잭션이 기준**이다. Redis 계산, HTTP 접수 시각, Kafka 재전달은 승인 확정이 아니다.

## S. 접수와 최종 결과

`202 Accepted`는 접수만 뜻한다. 서버가 마감 전에 계산을 시작했더라도 종료가 PostgreSQL에 먼저 확정되면 아직 정산되지 않은 승인 후보는 `AUCTION_ENDED`로 거절한다. 이미 확정된 요청의 결과는 재전달 뒤에도 바꾸지 않는다. 화면·REST·이벤트 형식은 유지하고 기존 거절 코드로 알린다.

## D/B. 같은 행에서 최종 결과 결정

| PostgreSQL에서 관측한 상태 | 처리 |
|---|---|
| 종료가 먼저 커밋됨 | 잠금 아래 `ENDED`를 확인하고 아직 정산하지 않은 승인 후보를 `REJECTED / AUCTION_ENDED`로 기록한다. 입찰 거절 원장, 요청 상태, `BidRejected` Outbox를 한 트랜잭션에서 저장한다. 경매 행과 기존 낙찰·유찰 결과는 수정하지 않는다. |
| 입찰 정산이 먼저 경매 행을 잠그고 성공적으로 커밋함 | 기존 버전 검사 후 승인·원장·Outbox와 새 마감 시각을 확정한다. 종료 작업은 잠긴 행을 건너뛸 수 있고, 이후 다시 선택할 때 최신 `ends_at`을 기준으로 삼는다. 마감이 연장됐으면 원래 마감 시각에는 종료하지 않는다. |
| 미종료 경매의 버전 불일치, 행 누락 또는 DB 오류 | 종료 거절로 바꾸지 않는다. 기존 실패·재시도 경계를 유지한다. |

입찰 정산은 **새 원장에 쓸 결정과 이벤트를 선택하기 전에** 종료 상태를 잠긴 행에서 확인한다. 중복 요청은 이미 확정한 결과를 우선하며, 잠금 뒤 관측한 상태로 기존 원장을 덮지 않는다. 처리 경계는 신규 승인·신규 거절·이미 확정된 요청을 구분해야 한다. 후속 자동입찰 상한 저장은 **Redis 승인 후보가 아니라 DB에서 새롭게 확정한 승인**일 때만 수행한다.

입찰 자격의 시각 기준은 계속 서버 `Clock`이다. `now >= endsAt`에 시작한 계산은 승인하지 않는다. 미종료 경매에서 승인 기준 시각에 5분 미만 남았다면 **기존 `endsAt`에 5분을 더한다**. 정확히 5분이면 연장하지 않으며 거절은 마감을 바꾸지 않는다.

## I. 재전달과 범위

종료 이벤트의 Redis 정리가 아직 실행되지 않아도 잠긴 PostgreSQL 상태로 거절을 확정할 수 있어야 한다. 같은 Kafka 요청이 다시 와도 원장과 Outbox는 추가하지 않는다. 커밋 실패는 성공으로 응답하거나 Kafka 처리 완료로 표시하지 않는다. Kafka 재발행, Redis 정리 정책, 기존 공유 데이터 보정, 신규 부하·AWS 실행은 포함하지 않는다.

## T. 로컬 검증과 완료 기준

1. **종료 선행:** 고정 서버 시각에서 승인 후보를 만든 뒤, 정산 저장 전에 별도 트랜잭션으로 종료를 커밋한다. Redis 정리 전의 후보를 처리해 거절 한 건·거절 이벤트 한 건을 확인한다. 승인·연장 이벤트와 자동입찰 상한 변경은 없어야 한다. 기존 낙찰·가격·버전은 그대로이고, 같은 요청을 재전달해도 중복이 없어야 한다.
2. **정산 선행:** 5분 미만 남은 입찰을 먼저 잠그고 커밋한다. 종료 작업이 원래 마감에서 낙찰을 만들지 못하며, 연장된 마감에서는 한 번만 종료하는지 확인한다.
3. **롤백과 회귀:** 종료 거절 경로에서 Outbox 쓰기가 실패하면 요청·원장이 함께 롤백되고, 다음 정상 처리에서 거절이 한 번만 남아야 한다. 미종료 행의 버전 충돌은 기존처럼 실패하며, 정확히 5분과 마감 시각 경계도 유지한다.

첫 실패 테스트는 고정 `Clock`과 트랜잭션 단계 제어를 사용한다. 임의 대기 시간으로 경합을 만들지 않는다. 구현 후 `make verify`와 격리된 테스트 DB를 사용하는 `make verify-integration` 결과를 남긴다.
