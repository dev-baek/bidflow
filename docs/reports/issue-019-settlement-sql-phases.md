# 정산 검증 SELECT 비용 분리 진단 결과

**격리 PostgreSQL에서 두 규모 모두 검증 호출에 성공했고, 4초 시간 초과는 재현되지 않았다.** 서버 텍스트 변환은 3.387–5.592ms였다. 이 결과로 실제 입찰 실행의 취소 원인을 판단하거나 스키마를 변경하지 않는다.

## 범위와 방법

[#331 사양](../specs/issue-019-settlement-sql-phases.md)에 따라 2026년 11월 25일 13:24:38–13:24:50 JST에 PostgreSQL 17.5 임시 컨테이너 하나에서 측정했다. 네트워크·공개 포트·영구 볼륨 없이 기존 마이그레이션을 새 DB 두 개에만 적용했다. 각 DB에 대상 경매의 요청·원장·결과 각 1,000건과 합성 배경 이벤트를 넣었다.

기존 SELECT 전체와 읽기 전용 트랜잭션, 서버 4초 및 호출 5초 제한을 유지했다. 각 규모에서 일반 조회로 결과 계약을 통과한 뒤, 3가지 관측을 순환하여 각 3회씩 실행했다. 준비 조회 2회와 측정 18개 모두 통과했다. 일반 조회는 기존 입찰 판정기와 합성 예상 결과에 모두 일치했고, 두 규모에서 같은 결과 해시가 나왔다.

## 측정 결과

표는 세 표본의 **중앙값 [최소–최대]**, 단위 ms다.

| 관측 | 무관 이벤트 2,000개 | 무관 이벤트 100,000개 |
|---|---:|---:|
| 일반 psql 전체 호출 | 240.354 [215.703–435.749] | 239.956 [236.868–246.022] |
| EXPLAIN 서버 실행, 변환 제외 | 36.631 [31.196–39.564] | 55.265 [54.809–56.804] |
| EXPLAIN 서버 실행, 변환 포함 | 46.144 [32.096–83.919] | 64.368 [61.680–79.489] |
| 변환 포함 실행에서 측정한 텍스트 변환 | 3.429 [3.387–5.592] | 4.419 [3.683–4.527] |

일반 psql stdout은 줄바꿈 포함 706,758바이트, EXPLAIN이 보고한 결과 변환량은 691kB였다. 모든 계획에서 Outbox는 순차 스캔이었고 대상 행 1,000개, loops 1이었다. Outbox 공유 블록 hit는 147 → 4,810으로 늘었고, 공유 블록 read는 두 규모 모두 0이었다. 상위 계획이 보고한 임시 블록은 두 규모 모두 read 4/write 28이었다. 이 수치는 계측 시점의 블록 접근이며 실제 물리 I/O 시간이나 CPU 시간으로 환산하지 않는다.

같은 합성 비교 안에서는 배경 이벤트가 많은 경우 Outbox 스캔 비용이 증가하는 신호를 확인했다. 그렇다고 과거 실측의 4초 취소를 설명하지는 못한다. 이번에는 텍스트 변환도 총 호출도 제한에 근접하지 않았고, EXPLAIN 서버 시간과 psql 전체 시간의 차를 순수 전송 시간으로 보지 않는다. #320의 인덱스 보류와 [#324의 같은 실행 원장·화면 대조 미완료](issue-019-settlement-wait-live.md)는 유지한다.

## 재현과 정리

Node.js 24, 로컬 Unix Docker 컨텍스트, 로컬에 있는 `postgres:17.5-alpine` 이미지가 필요하다. 기존 BidFlow Compose 서비스 5개는 시작하지 않고 상태만 비교하므로, 이 재현 스크립트는 해당 서비스들이 이미 healthy일 때 실행한다.

```sh
probe_dir=$(mktemp -d /tmp/bidflow-sql-phases.XXXXXX)
node scripts/run-settlement-sql-phases.mjs "$probe_dir/result"
```

원본 JSON과 실행 계획은 저장소 밖에 두고, [구조화 증적](evidence/issue-019-settlement-sql-phases.json)에 표본·결과 해시와 실행 파일 해시를 남겼다. 실험 컨테이너 제거, 기존 5개 서비스 상태 불변 및 기존 API readiness UP을 확인했다. 기존 DB 재조회, 새 입찰 부하, AWS 작업은 하지 않았다.
