# 격리 PostgreSQL 조회 호출 점검 결과

**가벼운 SQL과 약 644KB 결과를 반환하는 SQL을 포함한 24회 호출이 모두 5초 이내에 끝났다.** [#318](issue-019-settlement-outbox-index.md)의 호출 시간 초과는 이번 합성 점검에서 재현되지 않았다. 정산 SQL이나 인덱스는 실행하지 않았으므로 성능 비교는 여전히 미완료다.

## 호출별 결과

2026년 11월 24일 00:02:51~00:03:04 JST, 소스 `4b5ba1c6655ed80c60a8bcc6e2cc1687e7cc06e1`에서 실행했다. 별도 PostgreSQL 17.5 컨테이너는 네트워크·호스트 공개 포트 없이 시작했다. DB 데이터 경로는 임시 파일시스템을 사용했고 기존 볼륨이나 경매 데이터는 연결하지 않았다.

각 라운드에서 네 호출을 한 번씩 실행했고, 여섯 라운드에서 순서를 정방향과 역방향으로 번갈았다. SQL은 `docker exec -i`와 psql 표준입력으로 보냈으며 읽기 전용 트랜잭션·SQL 4초·로컬 프로세스 5초 제한을 그대로 사용했다. 출력 바이트와 내용이 기대값과 맞아야 성공으로 셌다.

| 호출 | stdout 크기 | 통과 | 경과 중앙값 | 최대 |
|---|---:|---:|---:|---:|
| psql로 `SELECT 1` | 2B | 6/6 | 180.92ms | 791.57ms |
| 같은 JSON 집계를 만들고 길이만 반환 | 7B | 6/6 | 179.69ms | 1536.43ms |
| JSON 1,000개 원소 전체 반환 | 644,001B | 6/6 | 193.82ms | 644.97ms |
| psql 없이 Docker 출력만 전송 | 644,001B | 6/6 | 186.88ms | 219.20ms |

크기는 끝의 개행을 포함한 실제 stdout 기준이다. 마지막 행은 같은 바이트 수의 NUL 데이터를 반환한다. 경과 시간은 Docker 명령 시작부터 프로세스 종료까지이며 PostgreSQL 서버 실행 시간만을 뜻하지 않는다. 최댓값은 전체 JSON이 아니라 길이만 반환한 호출에서 나왔다. 단일 로컬 세션의 결과로 큰 응답이 지난 시간 초과의 원인이거나 원인이 아니라고 단정할 수 없다.

## 정리와 다음 단계

실험 컨테이너를 제거하고, 기존 BidFlow 컨테이너 5개의 ID·시작 시각·healthy 상태가 변하지 않았음을 확인했다. 기존 API readiness는 UP이었다. 판정기 자체 점검 6개, 관련 Node 테스트 7개를 통과했다. [구조화 증적](evidence/issue-019-psql-call-probe.json)에 호출별 시간·바이트·판정을 남겼다.

후속 성능 비교는 새 격리 환경에서 호출 점검을 먼저 통과한 뒤 진행한다. 점검이 통과해도 [#317 사양](../specs/issue-019-settlement-outbox-index.md)의 읽기·쓰기 비교를 끝내기 전에는 인덱스를 적용하지 않는다. 이번 작업에서 인덱스 비교 재실행, 기존 DB 변경, 실제 입찰 부하, AWS 작업은 하지 않았다.
