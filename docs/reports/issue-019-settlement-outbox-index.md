# 정산 Outbox 부분 인덱스 비교 결과

[#317 사양](../specs/issue-019-settlement-outbox-index.md)에 따라 격리 PostgreSQL에서 기존 스키마와 부분 인덱스 후보를 비교했다. **작은 데이터셋의 조회 결과는 모두 일치했다. 다만 첫 반복 조회 호출이 5초 제한에 걸려 성능 비교는 미완료다. 인덱스 적용은 보류한다.**

## 격리 환경과 결과 동등성

2026년 11월 23일 19:22~19:24 JST, 병합 소스 `80b331d15d64f94ea4d581aa86af1eb81e86dfdf` 기준으로 진행했다. 첫 Docker 사전 점검은 컨테이너 생성 전에 종료됐다. 두 번째 시도는 사전 점검 여유만 늘렸다. PostgreSQL 17.5 컨테이너는 네트워크·공개 포트 없이 시작했고 기존 서비스의 볼륨은 연결하지 않았다. 두 DB에 동일 합성 데이터와 기존 스키마를 사용하고 후보군에만 실험용 인덱스 한 개를 추가했다. 관측 조회의 4초 SQL·5초 프로세스 제한은 유지했다.

대상 경매에는 승인 500건과 거절 500건, 다른 경매 등 무관 Outbox 이벤트 2,000개를 넣었다. 별도 2건 경매의 이벤트 2개 역시 대상 경매 조회에서는 제외됐다. 발행 전후 이벤트를 모두 포함했다. 다섯 조회 모두 인덱스 유무와 관계없이 스냅샷이 일치했다. 배열 순서를 맞춰 비교했으며 중복을 지우지 않았다.

| 조회 | 요청·원장·결과 | 상세 행 |
|---|---:|---:|
| 대상 경매 전체 | 1,000 / 1,000 / 1,000 | 1,000 |
| 같은 경매에서 두 요청만 선택 | 1,000 / 1,000 / 1,000 | 2 |
| 전체가 두 요청인 별도 경매 | 2 / 2 / 2 | 2 |
| 빈 경매 | 0 / 0 / 0 | 0 |
| 요청만 접수된 경매 | 1 / 0 / 0 | 1 |

정상 fixture는 기존 판정기를 통과했다. 합성 브라우저 자료로 최종 이벤트 불일치도 거부됨을 확인했다. 실제 브라우저나 HTTP 입찰은 실행하지 않았다.

## 실행 계획과 중단 지점

| 1,000건 조회의 Outbox 노드 | 기존 | 후보 |
|---|---:|---:|
| 실행 계획 | 순차 스캔 | 부분 인덱스를 사용한 비트맵 스캔 |
| 필터에서 제외한 행 | 2,002 | 0 |
| 공유 블록 접근(hit + read) | 147 | 149 |
| PostgreSQL EXPLAIN 실행 시간 | 71.65ms | 146.81ms |

후보가 무관한 행의 필터링은 없앴지만 이 데이터 배치에서 전체 Outbox 노드의 공유 블록 접근은 줄이지 못했다. EXPLAIN 실행 시간은 각 1회이며, 반복 호출의 중앙값이나 클라이언트 경과 시간이 아니다.

정상 결과와 실행 계획을 확인한 뒤 첫 반복 표본인 **기존군**의 `docker exec`/psql 호출이 5,057.32ms에 `ETIMEDOUT`으로 종료됐다. 확인된 것은 로컬 프로세스 제한이며 서버 statement timeout으로 분류하지 않았다. 실패 표본은 보존하고 자동 재시도하지 않았다. 계획한 6쌍 중 완성한 쌍은 0개다. 100,000개 확장 사례, 쓰기/WAL 비용, 인덱스 크기는 측정하지 못했다.

## 실험 환경 정리와 다음 판단

자동 정리 확인은 오류로 끝났으나 별도 조회에서 실험 컨테이너가 제거됐고 같은 날 생성된 미사용 볼륨이 남아 있지 않음을 확인했다. 기존 컨테이너 5개는 healthy, API readiness는 UP이었다. 기존 DB 변경·새 입찰 부하·AWS 작업은 하지 않았다.

합성 테스트 2개와 관련 단위 테스트 23개가 통과했다. 로컬 `make verify`는 프런트엔드 테스트 10개 및 워커 2개의 시간 초과로 중단됐다. [구조화 증적](evidence/issue-019-settlement-outbox-index.json)에 판정, 출력 해시, 측정 실패를 기록했다.

이번에는 성능 개선이나 쓰기 비용을 판정할 수 없어 기존 스키마를 유지한다. 후속 비교를 진행한다면 먼저 새 격리 환경에서 가벼운 psql 호출과 결과가 큰 읽기 호출을 나눠 실행 경계가 안정적인지 확인한다. 이번 결과로 [#316의 서버 쿼리 취소](issue-019-settlement-gate-live.md)를 해소했다고 판단하지 않는다.

[후속 호출 점검](issue-019-psql-call-probe.md)에서는 24회가 모두 5초 이내에 완료됐다. 합성 호출의 결과이며 이 성능 비교의 미완료 판정은 유지한다.
